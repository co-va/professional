# CORE HANDOFF — продукт, остатки и цены по местам покупки

Статус: **требуется отдельная реализация в `co-va/core`**. Этот файл находится только в `co-va/professional/staging`. Сам Core не изменялся.

## Утверждённая предметная модель

1. **Продукт (`InventoryItem`)** — сущность и характеристики независимо от остатка: производитель, название, тип, единица учёта/расхода (`unit`), номинал упаковки (`packageQuantity`), масса брутто/тары, артикул, штрихкод, правила использования (`canConsume`, `canSell`).
2. **Движение (`InventoryMovement`)** — приход, расход, продажа, возврат, списание или корректировка. Только движения влияют на остаток. Создание карточки продукта не создаёт приход.
3. **Остаток (`balance`)** — производный результат движений, только для чтения в карточке продукта.
4. **Места покупки / предложения поставщиков (`InventorySupplierOffer`)** — множественные независимые предложения для одного продукта; магазин и поставщик здесь равноправные источники приобретения, каждый со своими условиями и ценой.
5. **Базовая цена продукта** — ориентир/номинальная цена, которую задаёт пользователь независимо от последней закупки и от предложения любого поставщика.

## Что уже есть

- `GET /inventory` возвращает `items[].balance`, `lastPurchasePrice` и массив `supplierOffers`.
- В Prisma существует `InventorySupplierOffer`: `supplier`, `listPrice`, `discountPercent`, `actualPrice`, `supplierSku`, `note`, `isActive`.
- `POST /inventory/items` и `PUT /inventory/items/:itemId` сохраняют характеристики продукта. При `quantity > 0` создание товара пока автоматически создаёт «Начальный остаток»; Professional с этого этапа **не передаёт количество**.
- `lastPurchasePrice` не является независимой базовой ценой: она может изменяться при поступлении.
- Отдельных REST-операций для создания, изменения и архивирования `InventorySupplierOffer` нет. Импорт в сервисе существует, но не является публичным CRUD-контрактом.

## Необходимый API-контракт (к отдельной реализации в Core)

1. Добавить **независимую справочную цену за номинальную упаковку** (например, `referencePrice`) в `InventoryItem`: nullable, >=0; поддержка в создании, редактировании и `GET /inventory`. Не подменять ею `lastPurchasePrice`.
2. Ввести tenant-scoped CRUD для предложений конкретного продукта, например:
   - `POST /inventory/items/:itemId/offers` — создать;
   - `PUT /inventory/items/:itemId/offers/:offerId` — изменить;
   - `DELETE /inventory/items/:itemId/offers/:offerId` — деактивировать, **без удаления исторических закупок**.
   Поля: название места покупки / поставщика, прайс, скидка, итоговая цена, артикул поставщика, примечание; `offerId` стабилен.
3. **Цена предложения должна иметь понятное основание.** Хранить количество базовых единиц учёта в одном предложении (`unitsPerOffer` или эквивалент), т.к. один источник продаёт упаковку 100 шт., другой — поштучно. Не смешивать стоимость упаковки с себестоимостью одной штуки/грамма/миллилитра.
4. При приходе выбранное предложение может подставить источник, цену и пересчёт в единицы учёта, но **фактическую цену партии надо фиксировать в движении/лоте**; будущие изменения прайса не должны менять историю. Пример: 2 флакона × 250 мл по 500 ₽/флакон = приход 500 мл с себестоимостью 2 ₽/мл.
5. Проверять в Core изменение `unit` для продукта с движениями: нельзя молча переинтерпретировать накопленный остаток из «г» в «шт.»; нужна миграция/явное преобразование либо запрет.

## Что уже сделано в Professional

- Создание по `+`: только данные продукта, без начального остатка и без ввода закупочной цены.
- Полное редактирование: тип, способ использования, номинал, единица учёта, прочие характеристики.
- Показ итогового остатка и последней цены для чтения; при наличии — показ существующих предложений поставщиков **только для чтения**.
- **Запись множественных цен поставщиков и справочной базовой цены НЕ реализована до API.** Не создавать второй источник данных в локальном хранилище, auxiliary state или UI-заглушках.

## Границы

Core меняется отдельным исполнителем/этапом. Professional работает только в `staging`; `main` не изменять без разрешения владельца. Shared UI/геометрия Z/Q/X/V не меняются. CI не добавлять на текущем этапе.
